# Product show — interesting ways to demonstrate the product

Marketing pages die when every product gets the same layout: hero → logo cloud → 3 icon cards → testimonial → CTA.

Isa’s job: propose **proof that teaches** in under five seconds, tailored to this product — not decoration.

---

## Principles

1. **One strong demo beats four weak ones.**  
2. **Prefer real artifacts** (report, CLI, files, paths) over abstract illustration.  
3. **Label honesty:** mock vs live vs sample. Never fake a working control.  
4. **Novelty spends on proof**, not on confusing navigation.  
5. **Buyer learns a fact** — not “we’re innovative.”

---

## Mode catalog (pick 2+ per marketing pass)

### A. Artifact-first
**What:** The sample report / `panel-report` shape / CLI output is the hero visual.  
**Good for:** Trust, B2B, tools that produce documents.  
**Watch:** Artifact must be scannable; not a wall of markdown.

### B. Product path (code → agent → report)
**What:** Three-beat path of what happens in the repo.  
**Good for:** Developer tools, agent skills.  
**Watch:** Don’t fake browser chrome; keep it product-grade.

### C. Before → After (or broken → caught)
**What:** Show the failure the panel finds, then the fix or the finding.  
**Good for:** UX tools, audits, QA.  
**Watch:** Don’t shame the customer; shame the *problem*.

### D. Seat the persona
**What:** Named human (Riley / Avery) walks one flow in first person.  
**Good for:** Empathy products, multi-persona panels.  
**Watch:** One persona deep > three shallow.

### E. Live command as product
**What:** Install / run command is the product surface (copy block).  
**Good for:** CLI, npx, open source.  
**Watch:** Command must be real and publishable.

### F. Single interaction
**What:** One expandable, toggle, or tab that reveals depth (e.g. code | agent | report).  
**Good for:** Dense products without long scroll.  
**Watch:** Interaction must work; no fake tabs.

### G. Failure as teacher
**What:** Surface a real P0 the panel would file (with file path).  
**Good for:** Panel, linters, auditors.  
**Watch:** Specific path + severity; not vague “issues found.”

### H. Contrast (specific, not snark)
**What:** “Average agent pass” vs “panel report” with concrete differences.  
**Good for:** Differentiating from craft-only tools.  
**Watch:** No strawmen; no naming competitors unless true and fair.

### I. Empty → full proof
**What:** Show empty state of “no report yet” → after init → first findings.  
**Good for:** Lifecycle, onboarding products.  

### J. Chronology of a run
**What:** Timeline of phases (preflight → seats → report) with duration honesty.  
**Good for:** Multi-agent crews.  
**Watch:** Don’t invent timing.

## Scoring a demo idea

Rate 1–5 each; prefer total ≥ 16:

| Score | Question |
|-------|----------|
| Clarity | Job of product obvious in 5s? |
| Reality | Real artifact or honest sample? |
| Novelty | Not the default SaaS template? |
| Fit | Matches priority persona? |
| Preserve | Doesn’t kill install/CTA? |

---

## Pairing with design

| Demo mode | Needs from Craft / Frontend |
|-----------|-----------------------------|
| Artifact-first | Readable type, document chrome restraint |
| Path tabs | Real tab state, motion purposeful |
| Before/after | Toggle a11y, no misleading fake UI |
| Command | Copy button that works; contrast on dark bands |

Isa **proposes** modes and copy labels.  
Craft **vetoes** template DNA.  
Frontend **implements** after design brief.  
Motion **approves** if anything moves.

---

## Anti-patterns

- Six “feature” cards with icon + title + body  
- Lottie that doesn’t explain the product  
- Stock people pointing at graphs  
- Video that autoplays and says nothing scannable  
- Demo that requires a 2-minute tutorial to understand  

---

## Panel-native defaults (when dogfooding)

1. **Live command** + **artifact-first sample report**  
2. **Product path** (code → Run a panel → scores/P0s)  
3. Optional **failure as teacher** (one P0 with file path)

That’s enough. Do not add a fourth demo zone without cutting another section.
